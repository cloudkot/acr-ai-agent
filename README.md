# ACR AI Agent — Команда VlPKteam

[![Backend CI](https://github.com/cloudkot/acr-ai-agent/actions/workflows/ci.yml/badge.svg)](https://github.com/cloudkot/acr-ai-agent/actions)

Этот репозиторий — наше решение для кейса Академии цифрового развития. По сути, это ИИ-агент, который собирает образовательные программы. Методист вводит тему и часы, система предлагает каркас, проверяет арифметику, а после утверждения генерирует тесты, семинары, лекции и выгружает всё это в Word, PowerPoint и формат для LMS.

## 🚀 Как это запустить

Мы подготовили два способа запуска: через Docker (рекомендуется) и локально.

### Вариант 1. Docker (Всё в одном контейнере)
Внутри `Dockerfile` используется multi-stage сборка: сначала собирается React-фронтенд, а потом всё это упаковывается в легкий Python-образ. Контейнер работает от имени непривилегированного пользователя (`appuser`) и имеет встроенный `HEALTHCHECK`.

1. Создайте файл `.env` в корне (рядом с Dockerfile) и заполните ключи:
```env
OPENAI_API_KEY=ваш_ключ_от_Cloud.ru
OPENAI_BASE_URL=https://hub.gigaschool.ru/api/v1/llm/v1
```

2. Соберите и запустите:
```bash
docker build -t acr-agent .
docker run -d -p 8000:8000 --name acr-app --env-file .env acr-agent
```
Приложение будет доступно на `http://localhost:8000`.

### Вариант 2. Локальный запуск (для разработки)
Нам нужны Python 3.11+ и Node.js 20+.

**Бэкенд:**
```bash
cd backend
python -m venv .venv
source .venv/bin/activate  # Для Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

**Фронтенд (в отдельном терминале):**
```bash
cd frontend
npm install
npm run build  # Собираем в папку dist, откуда его забирает бэкенд
```
После сборки фронтенда бэкенд сам начнет его раздавать на `http://localhost:8000`.

## ⚙️ Переменные окружения
Мы используем `.env` файл. Вот что там должно быть (шаблон лежит в `.env.example`):
* `OPENAI_API_KEY` — ключ доступа к шлюзу GigaChat.
* `OPENAI_BASE_URL` — адрес шлюза. Если его не указать, возьмется дефолтный. При запуске сервера URL валидируется, чтобы приложение не падало в рантайме из-за опечаток.

## 🛠 Что под капотом

Мы не стали пихать LLM везде, где можно. Где-то используем классические алгоритмы и ML.

* **FastAPI + SQLite:** Само API и хранение сессий с логами аудита. Никаких словарей в памяти — всё пишется в базу.
* **Умный поиск (RAG + ML):** Для поиска по нормативке (273-ФЗ, Приказы 499/629) мы используем `scikit-learn` (TF-IDF + косинусное сходство). Это дешевле и быстрее, чем каждый раз скармливать нейросети весь справочник.
* **LLM Router:** Разные задачи требуют разных моделей. Для структуры мы зовем GigaChat Reasoning, для простых текстов — GigaChat-3-Pro.
* **Автоклассификатор:** Система сама понимает по описанию, это программа повышения квалификации (ДПО) или общеразвивающая, и подтягивает нужный шаблон.
* **Отказоустойчивость:** Все вызовы LLM обернуты в ретраи (3 попытки), есть таймауты, а JSON от нейросети проходит жесткую валидацию через Pydantic.

## 🎯 Соответствие требованиям кейса

| Что требовалось | Как сделали |
| :--- | :--- |
| Поддержка двух шаблонов АЦР | Автоматический выбор шаблона на основе запроса (`orchestrator.py`) |
| Карта компетенций (ЗУН) | Pydantic-модели, строгая структура (`schemas.py`) |
| Учебный план с проверкой часов | Валидатор проверяет сумму, плюс есть автокоррекция, если LLM ошиблась (`validator.py`) |
| Генерация контента | Тесты, семинары, лекции, **рабочие программы** и **библиография** (`content.py`) |
| Human-in-the-loop | Методист утверждает каркас до генерации контента, может точечно править (`main.py`) |
| Экспорт | Word, PowerPoint, LMS (формат GIFT) и полный JSON-дамп (`export.py`) |
| Прием референсов | Поддержка `.docx`, `.txt`, `.pdf`. Есть защита от больших файлов и Path Traversal. |
| Пометка источников | Если LLM не уверена в профстандарте, она ставит тег `[НЕПОДТВЕРЖДЕННЫЙ ИСТОЧНИК]`. |
